## 2026-10-12 · Sprint 4 训练循环：第 1 轮完成，第 2 轮进行中
**做了什么**
- 命令行沙盒 `python -m eval.sandbox`：自己扮演受访者，快捷操作 /whisper /angry /terse /stop /crisis /ai /takeover /handback /state。
- 接上真模型：AI 主持人用 DeepSeek（`deepseek-flash`），评分模型用腾讯云混元（`hy4-preview`），密钥由用户自己填进 `.env`。
- 提速：发现慢的主因是电脑的系统代理（走代理中位数 3.3 秒、偶发 23 秒；不走代理 0.7 秒），模型调用默认绕开系统代理（`MODERATOR_USE_SYSTEM_PROXY`）；给 DeepSeek 关掉"思考"。一轮从约 5 秒降到约 2.7–3.1 秒。
- 第一次真模型基线（每类抽 8 场，共 40 场）抓出引擎的真 bug 并修掉（第 1 轮）：
  - 收尾语、停止语、危机语没有如实回答"你是真人吗"（红线 H3），现在每个结尾都先如实回答；
  - AI 把问过的问题原样再问一遍（18 次），现在发声前拦截，兜底句也不重复；
  - 内部记录格式不对会让整句话作废，改为宽容处理；
  - 模型说"回答太短 / 跑题"同时又说"已回答"时，以前会翻页，现在只有真正回答了的才算完成。
- 评估度量修正：覆盖率只统计正常结束的访谈（受访者要求停止、危机本来就该提前结束），"覆盖"= 已问到或已被回答；报告只拿同类同规模的上一次运行对比。
- 第 2 轮（进行中）：让引擎真正执行"追问阶梯"（事实 → 行为 → 原因 → 情绪 → 价值）：回答没到"原因"层，或"值得深挖"分数够高，且这道题追问没用满 3 次、本主题还有时间，就继续追问，不翻页。
- 新增 `eval/analyze.py`：按类别汇总问题、延迟分解、摘出最差的对话。

**qa.sh 结果（第 1 轮后）**：571 / 1403 / 145 / 一键启动正常，全绿。第 2 轮代码改动后 moderator 相关 126 项测试通过，完整 qa.sh 待第 2 轮收尾时再跑。

**第 1 轮后的真模型指标（train，40 场）**：红线 0 违规；重复提问 0（达标）；必问要素覆盖率 96.5%（达标）；核心主题到达原因/价值层 93.4%（达标）；追问命中率 27%（门槛 80%）；时间偏差 ±15% 内的访谈占比 5.7%（门槛 100%，访谈过早结束，5–7 分钟结束 20 分钟的计划）；单轮延迟 p95 5.2 秒（门槛 3 秒）。

**还差什么**
- 第 2 轮结果待看（追问命中率、时间偏差应有改善）。
- 延迟：没被红线拦下重写的轮次 p95 3.7 秒，被拦下重写的轮次 5–8 秒；计划第 3 轮缩短提示词和内部记录、降低重写率。
- 提示词 v002（减少"Thanks for…"之类的重复客套、让主题聊深）。
- 停止条件：红线连续 3 次全量 0 违规、保留集质量全部达标、3 个随机种子稳定；最多迭代 10 轮，不放宽门槛。
- 全量训练集（240 场）回归、保留集（60 场）验收尚未跑。

**风险**
- 模拟受访者不是真人，分数只说明方向。
- 评分模型还没用 30 段人工打分的访谈校准，它的分数不作依据；"过渡时机正确率""收尾总结一致"需要人工标注，目前"未测"。
- 混元评分模型每次调用 7–21 秒（评估时才用，可接受）。
- 密钥曾出现在聊天和截图里：评估跑完后建议到 DeepSeek 和腾讯云后台删除旧密钥、重建，再填进 `.env`。
- 用 DeepSeek 给真人用之前，同意书已会写明"回答发给 DeepSeek"，上线前仍需律师审。
