# 阶段 2 · 「生成大纲」页设计要点（等用户确认效果图后开工）

效果图：`qa_shots/outline_wb_stage2_mockup.html`（6 个画面 × 3 种主题）。以下是效果图之外、写代码前要先定的规则。

## 1. 流程（四道关口）
1. **目标**：读项目已有的背景、目标，只问缺的。
2. **人群与执行**：读甄别问卷、招募方式、形式、时长，只问缺的；每轮最多 3 问，总共不超过 10 问；提问分 = 重要度 × (1 − 把握) × 影响面，低于 0.15 不问（用代码算）。
3. **大纲总览表（用户先确认）**：研究目的、要回答的问题、对象、形式与语言；每个模块一行（目的、要了解的内容、服务的问题、时长、题数、物料）+ 合计 + 检查。确认后才写题目。
4. **题目与定稿**：题目按每个模块的目的分别生成，可单独重新生成某个模块；之后用右侧对话框增删改查。

## 2. 建议（对话框底部，最多 3 条，可多选，点“采纳”才生效）
- **用户的要求（2026-11-18）：** 建议必须非常符合研究背景、研究目的和访谈人群，不能是通用套话。
- **做法：** 分两层。
  1. **规则层（代码，稳定、可测试）**：从总览/大纲算出“发现”——时长超或不足、顺序不合规（先无提示后有提示、价格在概念之后）、关键问题覆盖不足、物料太多或没轮换、备用时间没用、与人群/语言/形式不匹配（例如文字访谈出现“请出声描述”、长问卷对应的人群 5 分钟内的耐心等）。
  2. **措辞层（模型，只补措辞和理由）**：每条建议必须同时写出它依据的是**背景的哪句话、哪个研究目的、人群的哪个特征**；写不出依据的建议丢弃（页面上不显示）。模型只看背景、目标、人群描述和规则发现，不看受访者原话。
- **采纳后：** 只重排总览表，已写好的题目只重算受影响的模块，不动其他模块（用户 2026-11-18 确认）。
- **去重与排序：** 同类建议合并；按“影响研究目的的程度”排序，取前 3 条；“不再提醒”记在大纲上。
- **页面不写“发给某家 AI 服务商”（项目已定）；被问“你是什么模型”一律答“我是小星星助手”。**

## 3. 数据与接口（草案，写代码时再细化）
- 总览与题目都存阶段 1 的 `outline_items` / `study_settings`；建议是临时对象，不落库，只在采纳时生成 `revisions`（来源=generate，提出方=AI，状态待定）再由人接受。
- 新接口（`/api/projects/{pid}/outline-wb/...`）：读取/保存设定、三轮问答、生成总览、采纳建议、按模块生成题目、AI 对话（改写/加追问/插入/改名，最多 3 项，服务器校验后生成待定修订）。
- 红线检查：先做用户选的 A——拿 20 道真实题跑现有 12 条红线，看哪几条能直接用、哪几条要改、哪几条要另写“题目专用”规则，把结果给用户看，再接入修订的质检。

## 4. 用户已确认（2026-11-18）
- 建议来源：规则为主、模型补措辞，且必须贴合背景、目的、人群（见第 2 节）；采纳后只重排总览，已写好的题只重算受影响的模块。
- **追问深度**：总览表每个模块一列，用户直接选“不追问 / 追问 1 次 / 追问 1 次以上”；题目阶段每道题也可单独改。对应现有 `none / shallow / deep`；原来的 `free`（1–3 个不限）在这个页面不提供选项，旧数据里有的照常显示。
- **“备用”不再单独成行**：改成每个模块里可把某些题标成“备选”（时间有余才问，不计入总时长）。
- **题目按模块一个一个写、一个一个确认**（不是一次写完）。
- **版面**：不要横向通栏。步骤、模块、版本/语言/发布都放进左侧栏，成为“生成大纲”下的子栏；AI 对话框占满内容区高度，建议放在对话框最下方。
- 效果图（`qa_shots/outline_wb_stage2_mockup.html`）已确认，除上面这些调整外按图做。
