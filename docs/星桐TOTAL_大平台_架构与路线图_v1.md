# 星桐 TOTAL 大平台：架构与路线图 v1

> 定位：把现有的「定性深访 MVP」扩成 V3 蓝图里的**一体化平台**——定性（深访 1:1 + 座谈会 + 概念测试）、定量（外部问卷接入）、舆情采集，三种方法在「项目」层面真正打通；同时补全深访 MVP 没做完的部分。
> 本文是开发总纲：工程原则、统一数据模型、各模块边界与对接契约、**舆情从零全量设计**、分期路线、验收与测试。实现以本文 + `docs/星桐TOTAL一体化平台v3_设计规范与受访者端交互说明.md`（下称 V3 规范）为准。
> 用户 2026-10-15 拍板：定量=外部接入只做对接层；舆情=我全量设计满足甲乙方；立项向导/星图总览/多方法打通=做；深访缺失先补完；座谈会一起做；加快但**不准屎山代码、来回校验**。

## 0. 现状基线（已读代码，确认架构干净，可直接扩展）

- 中心实体 `Project`（`app/models.py`），一切带 `org_id` 做租户隔离；`Participant`、`Interview` 挂在 project 下。
- 迁移机制：启动时 `Base.metadata.create_all` 建新表 + `ensure_columns()`（`app/db.py`）自动补「可空 / 带标量默认值」的新列。**结论：新增表、新增可空列是安全的，已部署库无需手工迁移**；改类型 / 加 NOT NULL 无默认值要手工迁移。
- 路由统一范式（如 `app/routers/projects.py`）：Pydantic 校验 → `require_roles(*STAFF)` / `visible_interview()` 租户校验 → 业务 → `audit()` → 显式 `db.commit()`；越权一律 404。
- 外部能力走 provider 接口：`app/providers.py`（ASR/LLM）、`app/moderator/providers.py`（主持模型），mock 可离线跑测试。
- 前端 SPA：`app/static/index.html`（研究员端，哈希路由 `#/projects`、`#/p/<id>/<page>`、`#/i/<id>/<tab>`，导航在 `navHtml()`）+ `app/static/app.js` + `join.html`/`room.html`（受访者端）。
- 三层测试：`pytest` / `tests/qa_site.py` / `tests/e2e_room.py`，入口 `scripts/qa.sh`。

本次云环境已搭好并整套跑过一遍：**778 / 1823(+12 字体渲染误报) / 251 / 一键启动通过**（见 PROGRESS 2026-10-15 云环境条目）。

## 1. 工程原则（防屎山的硬约束，每个 Sprint 都要遵守）

1. **复用骨架，不另起炉灶**：新实体一律 `org_id` + `project_id` + 外键；所有查询带 `org_id`；越权 404；沿用 `audit()` 与保留期清理。
2. **迁移只做加法**：只新增表 / 可空列 / 带默认值的列，靠 `create_all` + `ensure_columns()`；不破坏已部署库。
3. **路由统一范式**：Pydantic + `require_roles`/`visible_*` + `audit` + 显式 commit；入站接口都要幂等、大小限制、速率限制。
4. **《代码质量宪章》**（CLAUDE.md）：函数 ≤150 行、类 ≤500 行；禁裸 except / except-pass，异常 logging 带 traceback（不记受访者原话）；常量与文案进各模块 `constants.py`；全类型注解 + docstring（写明 Raises）；状态用 `Enum` + 统一 `can_transition` 校验；外部调用超时 + 指数退避 + **接口注入便于 mock**。
5. **provider 化**：ASR/LLM/舆情数据源/情感模型全部走接口 + mock 实现，保证测试离线可跑、不用真实密钥。
6. **测试三层齐备**：每个功能配 pytest（逻辑/权限/租户/状态机）+ qa_site（页面：对比度/字号/点击区/溢出/四语/浅深主题）+ e2e（真流程）；新页面/路由**同步**加检查；`scripts/qa.sh` 全绿才算完成；**绝不放宽阈值 / 删检查**（要放宽先问用户）。
7. **隐私红线延续**：引文逐字来自服务器、不信客户端；受访者/公众 PII 最小化；保留期纳入新表；审计/接口不泄令牌、密钥、存储路径；受访者端不露内部信息。
8. **小步提交**：每个逻辑改动单独提交；每个 Sprint 单独 PR；PROGRESS 每做完一项就更新。

## 2. 统一数据模型（多方法如何打通）

一个 `Project` 下可并存多种「研究方法」。打通的关键是**聚合层**，而不是强行抽象。

- **采用「各方法各自建表 + 聚合视图」方案（渐进、低风险）**，不引入大一统父表：
  - 定性深访 / 座谈会：继续用 `Interview`，新增 `kind`（`depth` | `group`）区分；座谈会的多受访者用关联表（见 §4）。**不动现有深访归属与查询**。
  - 定量：新表 `Survey` / `SurveyResponse` / `ConceptMark`（外部推入，见 §5）。
  - 舆情：新表 `SentimentQuery` / `Mention` / … （见 §7）。
  - 都通过 `project_id` 归到项目。
  - （放弃「`Study` 抽象父表」方案：要动大量现有查询，风险高收益低，违背「简单=防屎山」。）
- **洞察池打通**：现有 `Insight` 绑 `interview_id`。改为可跨方法：给 `Insight` 增 `project_id`（可空，回填）+ `source_kind`（`interview` | `survey` | `sentiment`）+ `source_ref`。编码本 `Code` 已是 project 级，天然跨方法复用。→ 项目级「洞察池」把三方法洞察并列、统一编码、相互印证（三角验证）。引文仍逐字来自各自源（转写段 / 问卷开放题 / 舆情原文）。
- **参与者池打通**：`Participant` 已是 project 级；定量外部接入把「通过甄别的人」写进来（`screening` 字段已在），深访从同一池邀请 → 真正实现「先问卷甄别 → 再深访」。

## 3. 深访 MVP 补全（优先，先做完；对照 V3 第五部分差异表）

| 能力 | 现状 | 本路线处置 |
|---|---|---|
| 受访者登录（账号密码） | 无，凭邀请链接 | **不做**，维持邀请链接（除非甲方要求；更简单也更安全） |
| 预访问任务（pre-task） | 无 | **做**（Sprint 1） |
| 选时间 / 日历 / 提醒 | 研究员定时间 + .ics/文案 | **做**候选时间受访者自选（Sprint 1） |
| 物料圈选 / 概念测试圈选 | 概念测试已有展示，无圈选 | **做**圈选打点热区（Sprint 1） |
| 礼金 | 展示 | **不做**（已拍板不碰计费） |
| 座谈会 | 不做 | **做**（Sprint 2，见 §4） |
| 定量问卷旅程 | 不做（外部） | **外部接入**（Sprint 4，见 §5） |

补全项细节：
- **预访问任务**：研究员建场次时配置文字题（必填）+ 截图（可选）；受访者在同意后、候场前填写；答案进受访者档案，主持人房间内可见。新模型 `PreTask`（场次题目，JSON）+ `PreTaskAnswer`（答案，随保留期清理）。受访者端 `join.html` 增一步。
- **候选时间自选**：场次可配 2–3 个候选时间；受访者同意后在本人时区里选一个，确认写回 `Interview.scheduled_at`；站内状态 + 复用现有 .ics 下载；邮件/短信只留接口不实发（平台不发消息已拍板）。新模型 `TimeSlot`。
- **物料圈选**：受访者在物料（概念卡/图）上点按打点（♥ 喜欢 / ✕ 不喜欢，百分比坐标，跨屏一致）；视频物料暂停标注带时间点；汇总成热区进洞察。复用现有 `Stimulus`/`RoomState`；新模型 `StimulusMark`（随保留期清理）。与 §5 概念测试圈选**共用同一数据结构**。

## 4. 座谈会（定性 group，与深访大量复用）

**复用**：房间（LiveKit）、同意、设备检测、候场放行、录制合成、转写、实时字幕、洞察、片段——框架都在。

**差异（delta）**：
- `Interview.kind = group`；一场 group 关联多位 `Participant` → 新关联表 `InterviewParticipant`（多对一到 Interview；`InterviewObserver` 的模式照搬）。现有 1:1 代码走 `kind=depth` 不变。
- **LiveKit 令牌（`app/livekit.py`）**：把「只有 1 位受访者可发布」泛化为「每位受访者可发布」；观察员仍隐身只读；主持人全权；清场逻辑泛化。
- **录制合成（`app/recording.py` worker）**：现在混 moderator+participant 两轨；泛化为 **N 轨**（网格/并排布局 + 混音）。先支持 2 人跑通，再泛化 N。
- **转写（`app/pipeline.py`）**：每轨独立说话人；`speaker` 不再只有 `moderator`/`participant`，扩成编号参与者（隐私只显编号后两位）。
- **候场放行**：逐个放行多位；房间成员小窗显示「参与者 ·NN」。
- **受访者端 `room.html`**：能看到其他参与者（只编号，不露姓名/品牌/观察员）。
- **AI 主持**：座谈会**暂不接 AI**（先人工）；文中标注，留接口。

**风险**：N 轨混音布局/同步/回声；需把 `tests/e2e_room.py` 扩到 ≥3 位受访者。分两步：先 2 人，再泛化 N。

## 5. 定量（外部问卷接入，只做对接层）

**定位**：问卷、配额、质控、概念测试圈选由**外部问卷平台**完成；星桐只做「接入 + 归档 + 打通洞察/受访者池」。不在本仓库自建答题流程。

**入站 API（给外部平台调用，均带 org 校验 / 幂等 / 大小与速率限制 / 审计）**：
- **鉴权**：每个 org 一把「接入密钥」，HMAC 签名 + 时间戳防重放；密钥**只存哈希**，只在生成时显示一次。新模型 `IngestKey`。
- `POST /api/ingest/participants`：推送「通过甄别的受访者」到某 project（国家、语言、甄别题答案；姓名/联系方式可选；`external_id` 幂等去重）→ 落 `Participant`（`screening` 已有），甄别答案进档案 → 可直接邀请深访。**这就实现了「问卷甄别 → 自动进受访者池」**。
- `POST /api/ingest/survey`：推送问卷定义（题目/量表）+ 聚合结果 / 配额 / 质控状态 → 落 `Survey` + `SurveyResponse`（受访者可用 P 编号匿名）。
- `POST /api/ingest/concept-marks`：概念测试圈选热区（百分比坐标聚合）→ 与房间物料圈选（§3）**统一结构**，汇入洞察。
- 每次返回回执 + 写审计；webhook 可选。
- 出站（可选，MVP 先不做）：把「邀请/深访完成」状态回推外部，或提供只读 API。

**前端**：项目导航「定量」页——已接入问卷、完成/配额、质控状态、概念热区；「受访者招募」里把现在占位 `—` 的「甄别题答案」列填上。

**新模型**：`IngestKey`、`Survey`、`SurveyQuestion`、`SurveyResponse`（或聚合）、`ConceptMark`。

## 6. 立项向导 + 星图总览 + 多方法打通（项目层）

- **立项向导**（新建项目引导，多步表单）：① 基本信息（名/市场/语言/简报）② 选方法（勾选 深访/座谈会/定量/舆情，可多选）③ 各方法初始配置（深访：提纲模板；定量：生成接入密钥 + 对接说明；舆情：品牌/竞品/关键词/数据源）④ 团队与观察员 ⑤ 完成 → 进项目总览。后端：扩展 `POST /projects` + 各方法初始化接口；项目记录「启用了哪些方法」（`Project.methods` JSON 或 `ProjectMethod` 表）。
- **星图总览**（项目首页）：把三方法进度/关键指标汇成一张「星图」——每个方法一个节点，显示进度大数字 + 下一步 + 可点进入；三阶段色（橙/绿/金）。聚合：现有 `project_summary()` 扩成**按方法分组**（定性：场次/完成/转写/洞察；定量：问卷/完成/配额；舆情：监测量/负面占比/告警）。
- **洞察池**：跨三方法统一洞察列表 + 编码统计（支撑三角验证）。
- **导航重构（`navHtml()`）**：一级项 → 项目总览 / 立项向导 /（定性：受访者招募、场次与邀请、直播间、洞察与片段、编码与分析、物料与提纲、座谈会）/ 定量 / 舆情采集 / 设置；按角色与「项目启用的方法」显隐。**同步更新 `tests/qa_site.py` 的路由与检查**。

## 7. 舆情采集（从零全量设计 —— 重点模块）

### 7.1 目标与使用者
- **乙方**（研究机构 / 星桐自己）：跨品牌/品类做舆情监测与分析，产出给甲方的报告，并与深访/问卷三角验证。
- **甲方**（出海品牌）：看自己品牌 + 竞品在目标市场（先 SG，多语言 en/zh/ms/ta）的**声量、口碑、情感、话题、危机预警**。
- 一句话价值：把「公开讨论 + 评论 + 新闻 + 自有数据」变成**结构化、可逐字追溯、可竞品对比、可预警**的品牌健康洞察，并与定性定量同口径打通。

### 7.2 合规姿态（先定红线，再谈功能）
- 星桐是 processor；数据放新加坡；延续保留期与审计。
- **不自己爬虫**（CLAUDE.md 明确「不做爬虫」）。数据只来自：① 平台**官方 API / 开放数据**（遵守 ToS 与配额）；② **持牌第三方舆情数据供应商**（采购）；③ **甲方自有数据**（自家电商评论、客服记录、私域、问卷开放题）；④ **平台内部跨方法数据**（深访转写、问卷开放题）。
- 每条数据记「来源 + 授权状态 + 采集方式」；对公开个人言论**最小化**（只存平台公开 ID/链接的哈希，不额外富集画像）；提供删除/撤回通路；报告默认脱敏（不点名普通个人）。
- 情感/话题模型走 provider 接口；若用云端模型，数据出境须落在甲方授权与同意框架内（与现有出境同意逻辑一致）。
- **不存平台原文媒体文件**，只存文本 + 链接 + 元数据（与「不下载原始录像」一致，降版权/合规风险）。
- **待用户拍板的合规门**（见 §9）：接哪些平台 API / 买哪家数据源 / 甲方数据接入方式 / 是否允许云模型处理公开评论 / 各法域。**S1–S4 用 mock + 内部数据即可跑通，不阻塞。**

### 7.3 数据源与采集（连接器架构）
- Provider/Connector 接口（照 `providers.py`）：`SentimentSource` 抽象 `fetch(query, since) -> list[RawMention]`。实现：官方平台 API、数据供应商 API、甲方 CSV/API 导入、内部数据（转写/开放题）适配器；**mock 连接器**供离线测试。
- 采集：按 project 的「监测查询」（品牌/竞品/产品/关键词 + 语言 + 市场 + 时间窗）定时拉取（后台 worker，照 `recording.py` worker 模式）；去重（URL/平台 ID/内容哈希）；限速与配额；失败重试 + 记录（不吞异常）。

### 7.4 处理与富集（NLP 流水线，全 provider 化）
标准化成一条 `Mention` 后依次：语言检测 → 清洗去噪 → 垃圾/机器人过滤 → **实体链接**（品牌/竞品/产品，带别名词典）→ **话题/方面抽取**（aspect：价格/成分/功效/包装/物流/客服…）→ **情感**（文档级 + 方面级 ABSA：正/负/中 + 置信度）→ **情绪**（喜怒等）→ **意图/购买信号** → **关键句/逐字引文抽取**（可回链原文，延续「引文逐字」原则）。
- 每步走模型 provider（可 mock）；结果带置信度；低置信标「待人工复核」；人工可纠正（回流改进）。
- 多语言：en/zh 先行；ms/ta 质量未验（与转写一致的已知风险，文中标注）。

### 7.5 数据模型（舆情，均带 org_id + project_id，纳入保留期清理）
- `SentimentQuery`：监测配置（品牌/竞品/关键词/语言/市场/源/时间窗/开关）。
- `SentimentSourceAccount`：数据源凭据（加密/哈希，不回显）。
- `Entity`：品牌/竞品/产品 + 别名词典。
- `Mention`：一条言论（source, source_id, url, author_ref=脱敏哈希, lang, text, published_at, fetched_at, reach 指标, dedup_hash, raw_meta JSON）。
- `MentionEnrichment`：entity 链接、overall_sentiment、confidence、emotions、topics、intent、is_spam、needs_review、model_ver。
- `AspectSentiment`：mention_id、aspect、sentiment、confidence、quote（逐字）。
- `SentimentAlert`：规则命中（突增/负面激增/危机词）；level（red/yellow）、reason、window、status。
- 结论复用统一 `Insight`（`source_kind=sentiment`），引文来自 `Mention` 原文。

### 7.6 分析与看板（满足甲乙方需求）
- **概览**：总声量 + 趋势（时间序列）、净情感、情感分布、环比。
- **竞争**：Share of Voice（我 vs 竞品）、各家情感对比、方面雷达。
- **话题**：热门/新兴话题（上升最快）、话题 × 情感热力图、可点进原文的词云。
- **方面（ABSA）**：价格/功效/成分/物流/客服… 情感条，定位口碑强弱项。
- **情绪 & 危机**：情绪分布；负面激增/危机预警时间线。
- **画像（聚合、不点名）**：地域/语言/平台/来源类型分布；高触达来源（仅聚合）。
- **钻取**：任何图都能下钻到**逐字原文 + 链接**（可追溯）；一键把一条原文「存为引文/洞察/追问」，与深访引用机制统一。
- **导出**：甲方报告（Word/CSV/看板分享，默认脱敏、可加水印，复用分享链接机制）；研究团队全量视图。

### 7.7 告警
- 规则：声量突增（×基线）、负面占比破阈值、危机关键词（安全/法律/健康）、竞品异动；窗口可配；命中生成 `SentimentAlert` + 站内红/黄标（复用 AI 房间红黄语义）；不实发邮件（留接口）。

### 7.8 与定性/定量打通（TOTAL 的意义）
- **内部数据反哺**：深访转写、问卷开放题可作为 `Mention` 源，进同一舆情分析（统一话题/情感/方面词典）→ 真正「定量+定性+舆情」同口径。
- **洞察池**：三方法洞察统一编码 + 导出 + 相互印证（例：舆情「价格负面 ↑」对上深访「嫌贵」对上问卷「满意度低」）。
- **星图**：舆情作为项目一个方法节点，进度/指标汇总。

### 7.9 舆情分期（子冲刺）
- **S1** 数据模型 + mock 连接器 + 采集 worker（离线可跑、可测）。
- **S2** 富集流水线（provider 化：语言/情感/话题/ABSA/实体，mock + 真模型）+ 引文逐字。
- **S3** 看板与钻取 UI（概览/竞争/话题/方面/情绪）+ 导出。
- **S4** 告警 + 与定性定量打通（内部数据源 + 洞察池）。
- **S5** 接真实数据源（待 §9 合规门拍板）+ 多语言验证。
