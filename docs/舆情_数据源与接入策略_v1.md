# 舆情采集：数据源与接入策略 v1

> 用户 2026-10-15 授权「你来定，大陆和海外所有主流都考虑」。本文把数据源一次性定清楚：有哪些源、各自怎么合规接入、分几档预算、按什么顺序上。
> 配套总纲见 `docs/星桐TOTAL_大平台_架构与路线图_v1.md` §7。实现以本文为准，变更升版本号。

---

## 0. 一句话结论（我的建议方案）

**用一套统一的「连接器」接口（`SentimentSource`），分三档上线：**
1. **Tier 0（马上做，S1–S4，零/低成本、完全合规）**：平台内部数据（深访转写 + 问卷开放题）+ 甲方自有数据导入 + 免费官方/开放 API（GDELT 新闻、Reddit、YouTube、App Store / Google Play 评论）+ mock 连接器。**不买任何东西就能把整条流水线和看板跑通。**
2. **Tier 1（申请官方 API）**：X/Twitter、TikTok Research、Meta Content Library、YouTube、Reddit —— 覆盖海外主流社媒，首批市场 SG 优先。
3. **Tier 2（采购持牌供应商，覆盖"没有干净官方 API"的长尾）**：海外选 1 家（Brandwatch / Meltwater / Talkwalker 之一）；大陆选 1 家综合（慧科 / 数说故事 / 识微）+ 1 家红抖电商（千瓜 / 飞瓜 / 蝉妈妈）。

**红线（CLAUDE.md）**：星桐**不自己爬虫**。数据只来自 ①平台官方 API / 开放数据 ②持牌第三方供应商 ③甲方自有数据 ④平台内部数据。只存文本 + 链接 + 元数据，**不存平台原文媒体文件**；个人言论最小化、报告默认脱敏。

## 1. 合规框架（先定，再谈源）

| 维度 | 规定 |
|---|---|
| 星桐角色 | processor（处理者）；数据放新加坡；纳入保留期与审计 |
| 采集方式 | 只走官方 API / 持牌供应商 / 甲方授权数据 / 内部数据；**禁止自建爬虫**；供应商也须是合规持牌（能提供数据来源与授权证明） |
| 存储 | 只存文本 + 原文链接 + 元数据 + 脱敏作者标识（哈希）；不落媒体文件；raw_meta 存平台返回的结构化字段 |
| 个人信息 | 公开言论最小化，不额外富集画像；提供删除/撤回；报告默认不点名普通个人，只聚合 + 代表性引文（可去标识） |
| 出境 | 用户已授权**允许云端大模型处理公开评论**（2026-10-15）；仍须落在甲方授权/同意框架内，敏感品类单独评估 |
| 法域 | SG PDPA（首批市场）、中国 PIPL（运营主体）、各平台 ToS、配额与署名要求；默认回避 GDPR 区（与现有 BLOCKED_COUNTRIES 一致） |
| 开发期例外 | 造样本/评估数据时，可用 agent 侧工具（见 §5）在 ToS 允许范围内取少量样本，**仅供开发测试，不进产品数据通路** |

|---|---|---|---|---|

| **Threads** | 官方 API（成长中）；供应商 | Tier1 | 中 | |

## 3. 大陆主流数据源

> 大陆平台普遍**没有对外开放的内容检索 API**（小红书、微信、抖音尤甚），合规做法是**采购持牌舆情/数据供应商**，由供应商承担采集合规；不自建爬虫。

| 平台/源 | 合规接入方式 | 成本档 | 优先级 | 备注 |
|---|---|---|---|---|
| **微博** | 微博开放平台（受限）；舆情供应商（主力） | Tier2 | 高 | 中文舆情主战场 |
| **微信**（公众号/视频号） | 无开放检索；新榜 / 清博 / 慧科 等供应商 | Tier2 | 高 | 影响力大、最难，必须买 |
| **抖音** | 巨量开放平台（偏广告/自有号）；飞瓜 / 蝉妈妈 / 新抖 供应商 | Tier2 | 高 | 短视频 + 评论 |
| **小红书** | 无官方内容 API；千瓜 / 灰豚 / 新红 供应商 | Tier2 | 高 | 出海品牌 + SEA 华人重度 |
| **B站** | 有较开放 API（视频/评论/弹幕）；供应商 | Tier1 | 中 | 可较低成本接 |
| **知乎** | 无开放；供应商 | Tier2 | 中 | 深度讨论/长文 |
| **快手** | 供应商 | Tier2 | 中 | 下沉市场 |
| **今日头条/西瓜** | 供应商 | Tier2 | 中 | 资讯 |
| **贴吧 / 豆瓣** | 供应商 | Tier2 | 低 | 社区口碑 |
| **黑猫投诉** | 供应商 / 页面开放数据 | Tier2 | 中 | 投诉/危机信号强 |
| **电商评论**（天猫/淘宝/京东/拼多多） | 生意参谋（甲方自有）/ 供应商；甲方店铺数据 | Tier2 | 高 | 甲方自家数据最干净合规 |
| **新闻/资讯** | 慧科(Wisers) / 知微 / GDELT 中文 | Tier0/2 | 高 | |

## 4. 供应商候选（采购清单，Tier 2）

**海外社媒监听平台（选 1，覆盖多平台 + 持牌数据）**：
- **Brandwatch**（Consumer Research，老牌，X/Reddit firehose 授权、全球多语言）
- **Meltwater**（媒体 + 社媒 + PR，覆盖广）
- **Talkwalker**（视觉识别 + 多语言强）
- 其它：Sprinklr、Synthesio、NetBase Quid、Pulsar、YouScan（图像）、Brand24 / Determ / Mention（中小预算）

**海外合规数据 API（按量付费，适合自建看板补数据）**：
- **Bright Data**（主打合规数据集/采集）、**DataForSEO**（SERP/评论）、**ScrapeCreators**（Reddit/TikTok/YT/IG/LinkedIn/Threads，`SCRAPECREATORS_API_KEY`）、**Apify**（各平台 actor）。
  - ⚠️ 这些偏「采集即服务」，用于产品前须确认其合规与授权；**优先官方 API + 老牌持牌平台**。

**大陆舆情/数据供应商**：
- 综合舆情（选 1）：**慧科讯业(Wisers)**、**数说故事(DataStory)**、**识微商情**、新浪舆情通、清博智能、蚁坊(鹰眼速读网)、军犬、智慧星光、百度舆情。
- 红/抖/电商垂直（选 1–2）：**千瓜数据**（小红书）、**飞瓜数据**（抖音）、**蝉妈妈**（抖音电商）、新榜(newrank，微信/全域)、灰豚、GSDATA。

## 5. 连接器架构（怎么把这些源统一接进来）

统一接口（照 `app/providers.py` 风格，均可 mock 离线测）：

```
class SentimentSource(Protocol):
    name: str
    def fetch(self, query: SentimentQuery, since: datetime) -> list[RawMention]: ...
```

- 每个源一个实现类：`GdeltSource`、`RedditSource`、`YoutubeSource`、`AppStoreSource`、`CsvImportSource`（甲方数据）、`InternalSource`（深访转写/问卷开放题）、各供应商 `WisersSource` / `BrandwatchSource` / `QianguaSource` …，外加 `MockSource`（测试）。
- 凭据存 `SentimentSourceAccount`（加密/哈希，不回显）；缺凭据的源在 UI 标「未接入」。
- 采集 worker（照 `app/recording.py` worker 模式）：按 `SentimentQuery` 定时拉取 → 去重（URL/平台ID/内容哈希）→ 落 `Mention` → 进富集流水线（§7.4 总纲）。限速 + 配额 + 失败重试 + 记录（不吞异常）。
- **Tier 0 先实现**：`MockSource` + `InternalSource` + `CsvImportSource` + `GdeltSource`（免费新闻，验证真实外部源打通）；其余源逐档加，**不改下游**（富集/看板/告警与源解耦）。

## 6. 预算分档（供用户选，具体数字以采购实报为准）

| 档 | 内容 | 大致成本 | 能做到什么 |
|---|---|---|---|
| **A 零预算** | Tier 0：内部数据 + 甲方数据 + GDELT/Reddit/YouTube/App 评论免费档 | ¥0（只耗开发） | 整条流水线 + 看板 + 告警跑通；覆盖新闻/部分海外社媒/App 与自家电商评论 |
| **B 轻量** | A + X Basic + 1 个按量数据 API（如 DataForSEO/ScrapeCreators）+ 千瓜/飞瓜之一 | ~¥数千–2 万/月 | 海外主流社媒 + 小红书/抖音垂直打通 |
| **C 专业** | B + 1 家海外监听平台（Brandwatch/Meltwater/Talkwalker）+ 1 家大陆综合（慧科/数说故事/识微） | ~¥数万–数十万/年 | 大陆 + 海外全主流、持牌合规、竞品对标、历史回溯 |

**建议**：先走 A 把产品做扎实（S1–S4 不花钱），到 S5 再按甲方项目实际需要选 B 或 C（通常按单个甲方项目的预算采购对应源）。

## 7. 多语言（en/zh/ms/ta）
- 情感/话题模型：en/zh 成熟；**ms（马来语）/ta（泰米尔语）质量未验**（与转写的已知风险一致）。
- 处置：先 en/zh 上线；ms/ta 在 S5 用真实数据抽样评估，必要时换/微调模型或供应商；未验前在看板标注置信度与语言覆盖。

## 附：与 skill 生态的关系（已排查，2026-10-15）
- 已用 `npx skills find` 搜 sentiment / social listening / brand monitoring：相关技能多为**方法论**（如小红书 social-listening 工作法）或**爬取型数据服务**（ScrapeCreators、Apify）。
- 方法论技能已吸收进本文与总纲 §7.6 的看板/告警设计。
- 爬取型服务**仅可用于开发期造样本/评估数据**（ToS 允许范围内），**不进产品数据通路**（产品守「不自建爬虫、只用官方 API/持牌供应商」红线）。
