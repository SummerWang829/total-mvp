## 第一批：视觉改版（先做这个，做完给我看）

目标：现在界面太素、像半成品，要接近 v3 原型的质感。

1. **研究员/客户端框架**
   - 左侧深绿导航（宽 244px，吸顶），当前项有橙色竖条；手机宽度时变成顶部横向滚动。
   - 项目内顶部“项目上下文栏”：项目名、阶段轨道、当前状态，吸顶半透明。
   - 项目总览首页：整体进度大数字 + 分项进度 + 下一步提示 + 最近动态。
2. **项目列表**：卡片带状态标签、受访者数、下一场时间；顶部有搜索和状态筛选。
3. **访谈列表**：改成表格（手机上变成卡片），按“进行中/待开始/已结束”分组，最新的在最前；每行有状态标签、时间、主持人、操作按钮。
4. **组件统一**：按规范 1.5 做按钮、标签、表格、表单、弹窗、提示条；悬停铺色动效在“减少动效”下关闭。

### 访谈房间的主题：默认白色浅色，可切换成深绿色

我（用户）的要求：开会的背景**默认应该是白色浅色**，更漂亮；用户可以自己改成深绿色。

- 房间页（主持人、受访者、观察员三种角色的页面）默认用**白色浅色主题**：白底、墨绿文字、橙色强调，视频小窗用浅灰底，说话者描边用橙色。
- 房间页右上角放一个主题切换（浅色 / 深绿），选择后立刻生效。
- 选择**记在浏览器里**（localStorage，读写都要 try/catch，读不到就用浅色），下次进入沿用；不要因此影响别人或服务端。
- 深绿主题沿用规范 1.2 里的 `--room` 系列色（#0E1A16 / #15271F / #24413A / #E8EFEA）。
- 两个主题都要满足：文字对比度 ≥ 4.5:1、手机点击区 ≥ 36px、录制指示（红点 + “正在录制/Recording”）清晰可见、按钮禁用态可辨认、聚焦环可见。
- 摄像头关闭时的占位、字幕、聊天、转写区在两个主题下都要好看，不能只调了一个。
- 受访者端房间：同样默认浅色。受访者页面语言仍跟随同意书语言，切换按钮文字要有四种语言版本（en/zh/ms/ta）。
- `tests/qa_site.py` 和 `tests/e2e_room.py` 里对房间页的审计（对比度、字号、点击区、溢出）要**在浅色和深绿两个主题下各跑一遍**。
- 规范 1.7 和第二部分里关于房间“深色”的描述，要同步改成“默认浅色，可切换深绿”。

## 第二批：补齐缺失功能（按这个顺序，一项一项做，每项做完跑 qa.sh）

对照规范第五部分的差异表。

1. **受访者设备检测页**：摄像头、麦克风（带音量条）、扬声器（播放提示音）、网络；失败项红字加具体处理办法；通过后才能进候场/房间。四种语言。
2. **受访者选时间与提醒**：研究员给出候选时间，受访者按本人时区选择；确认后生成日历邀请（.ics）和开始前 1 小时提醒（先做站内状态，邮件/短信发送先留接口）。
3. **候场室与放行**：受访者进入后先在候场室，主持人在“场次设置”里逐个放行或暂缓；未放行的人进不了房间。
4. **受访者招募与分配**：研究员录入/导入受访者、按国家和标签筛选、分配到场次、发送邀请。
5. **访谈提纲与物料**：提纲分段，主持人在房间里能看到当前段；物料（图片/概念卡）可在房间里展示给受访者。
6. **观察员私聊与标记**：观察员给主持人发私聊（受访者看不到）；观察员在转写上标记片段。
7. **洞察导出**：洞察结论导出为 Word 或 CSV，包含证据原文和时间点；不包含受访者姓名和联系方式。
8. **用户与权限管理**：管理员邀请同事、设置角色（管理员/研究员/主持人/观察员）。
9. **预访问任务**（可选，最后做）。
