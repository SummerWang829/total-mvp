# 舆情监测与数据采集方案 v1（2026-10-18）

目标：把公开渠道上消费者怎么说（评论、帖子、新闻），采进星桐，打上语言/情感/话题，和访谈、座谈会、问卷放在同一个项目里互相印证。

## 1. 世界上主流公司怎么做（查证结果，来源见末尾）
1. **不自己爬社交平台，靠授权的数据通道。** Brandwatch、Meltwater、Talkwalker、Sprinklr、Cision 的“数据”大多是向平台买的官方授权：早年是 Twitter 的 firehose（经 Gnip 等转售商），Reddit 有官方数据合作（Brandwatch、Meltwater、Sprinklr、Talkwalker 都公布了合作）。新闻、博客、论坛、评论站才是它们自己大规模采集。
2. **平台收紧授权。** Reddit 要求事先申请批准，商业用途要另签协议；Twitter 早已停止对第三方转售全量数据。所以“买得到的官方通道”窄而贵。
3. **中间还有一层数据供应商**（Bright Data、Apify 等）：把公开、不登录的页面做成接口按量卖。覆盖广、上手快，但**合规风险转给使用者**——供应商的法律声明不会替你承担责任。
4. **开源只做“采集框架”**：Scrapy（Python，大规模静态页）、Crawlee/Playwright（JS 渲染页）、Firecrawl（把网页变成给大模型的干净文本）。没有哪个开源项目替你解决授权问题。
5. **分析层**：多语言情感用 XLM‑RoBERTa 类模型（cardiffnlp 的 twitter‑xlm‑roberta）做整句极性；“按属性的情感”（价格/包装/客服各自褒贬）要 ABSA 框架（PyABSA）或直接用大模型。我们已有大模型通道，先用大模型批量做，量大了再换本地小模型降成本。
6. **开源舆情项目**：有几个自托管的小项目（如 Radar、TrendRadar），说明“新闻 + RSS + 少数平台 + 大模型情感”的轻量组合是可行的；它们不是合规保证，不直接引入。

## 2. 我们的做法：分三层通道，合规的先上
| 层 | 通道 | 例子 | 合规风险 | 状态 |
|---|---|---|---|---|
| 1 官方/授权 | RSS/Atom（媒体、品牌官方号、博客）、Apple App Store 评论 RSS、YouTube Data API（官方，有配额）、Reddit 官方 API（要平台批准） | 新闻、App 评论、品牌 YouTube 评论 | 低 | S1 先做 RSS、App Store、测试用模拟源；YouTube/Reddit 留接口，等密钥/批准 |
| 2 供应商 | 供应商的接口（Apify、Bright Data 等），用你们自己的密钥 | TikTok、Instagram、Shopee/Lazada 评论 | 中：风险在使用者 | S3 做“供应商连接器”，要你先选供应商并让法务看合同 |
| 3 自己抓公开网页 | 论坛、评论站、公开网页：不登录、遵守 robots.txt、限速、标明身份 | HardwareZone、Lowyat、Mumsnet 一类 | 中：逐站评估条款 | S2 做“礼貌抓取器”（现在已有安全抓取层），每个站点上线前过检查清单 |

**明确不做**（原因都是违反平台条款或法律风险高，我不会写）：登录后抓取、用账号池/Cookie、绕过验证码或反爬、抓私密群和私信、画像到个人。小红书/抖音这类没有官方公开接口的平台，**只走供应商或人工导入**，不自己破解。

## 3. 数据流水线
采集（连接器）→ 去重（URL/正文哈希）→ 清洗（去 HTML、截长）→ **富集**（语言识别、情感、话题/属性、实体；大模型批量）→ 入库 → 看板（声量、情感趋势、话题榜、典型原话）→ 告警（负面突增）→ 与定性打通（把某个话题一键变成访谈提纲/研究假设，把访谈洞察和舆情声量放在一起看）。
- 每条“提及”只存：正文、链接、发布时间、来源、作者的**加盐哈希**（不存昵称/头像）、互动数。
- 原文保留期默认 180 天后只留聚合统计；支持“按链接或作者哈希删除”（下架请求）。

## 4. 合规与安全（写进代码）
- **SSRF 防护**：研究员填的网址会被服务器去抓，所以只允许 http/https，解析后拒绝内网、回环、云元数据地址，重定向每一跳重新检查，大小和时间有上限。
- **礼貌**：固定、可识别的 User‑Agent；遵守 robots.txt；同一站点最少间隔 2 秒；不带 Cookie。
- **新加坡 PDPA**：公开可得数据可适用“公开可得”例外，但要“合理”，且目的限定；PDPC 对生成式 AI 的草案指引也强调公开可得例外和逐案评估。我们按“最小化存储 + 目的限定 + 可下架”设计。**这不是法律意见，上线真实数据源前请法务过一遍。**
- 供应商数据：合同里要有“数据来源合法”的陈述与赔偿条款。

## 5. 分期
- **S1（本次）**：数据模型、连接器接口、安全抓取层、模拟源 + RSS + App Store 连接器、采集任务（定时 + 立即运行）、去重、富集（大模型批量，离线有模拟）、API、项目页“舆情监测”（来源管理、声量/情感/话题、原文列表、下架）、测试。
- **S2**：看板钻取与导出、负面告警（邮件，等发信服务）、礼貌网页抓取器 + 站点检查清单、YouTube 官方接口。
- **S3**：供应商连接器（你选供应商）、与访谈打通（话题 → 访谈提纲/假设；洞察池）、Reddit（拿到批准后）。
- **S4**：本地小模型降成本、多语言（马来/泰米尔）质量评估、按属性的情感评估集。

## 6. 要你定的事
1. 先盯哪些品牌/品类、哪些国家（决定要哪些来源）。
2. 供应商要不要买（预算档：A 零预算只用官方/开放通道 / B 加一家供应商 / C 全套）。
3. 法务：公开数据采集的合规意见（PDPA + 平台条款），尤其是论坛站点与供应商。
