# 项目固定规矩（开发与交付）

> 适用：星桐 TOTAL 深访平台 `total-mvp` 的全部开发、验证、部署、同步工作。
> 任何接手开发的人或 AI（包括 Claude Code、WorkBuddy）都必须遵守。
> 用户 2026-11-03 确认生效。修改本文件需用户确认。

---

## 一、代码质量（规矩 1–3）

**1. 代码正规，不写屎山**
- 按现有目录分层放文件：页面逻辑进 `app/static/` 对应 `*.js`，样式进对应 `*.css`（外壳 `ui_v11.css`、问卷 `ui_screening.css`、通用 `app.css`），不要新建平行体系。
- 一个函数只做一件事；命名用完整词（`openRecruitDialog` 而不是 `ord`）；魔法数字要提成变量或写注释说明来源。
- 改样式前先确认选择器有对应 DOM（在浏览器里查一遍再改），不凭猜测改 CSS。**本项目已踩过坑**：`#rfws .rq-opt` 没有对应节点，真正的选项行是 `.rf-optrow` / 容器 `.rf-optl`。
- 不复制粘贴大段代码；同类逻辑抽公共函数。

**2. 每个文件有标签、有目录，便于自查**
- 新增 JS/CSS 文件必须在文件头写注释块：模块名、负责的页面、依赖的其他文件、最后修改日期。
- 新增文件必须同时更新 `docs/PROGRESS.md` 里对应条目，说明这个文件干什么用。
- 项目结构变化（新增目录、拆文件）要在 `docs/PROGRESS.md` 记录一笔，避免后面的人找不到东西。

**3. 不自作主张扩大改动范围**
- 只改与需求相关的文件。顺手发现的其它问题，写进汇报的「建议」里，不擅自改。
- 需要改公共文件（外壳、`app.css`、`shell.js`）时，先确认影响范围（哪些页面共用），并在汇报里写明。

## 二、验证与汇报（规矩 4–6）

**4. 自查通过才通知用户**
交付前必须自己跑完这套检查，全部通过才汇报：
1. 页面打得开：本地起服务 + 浏览器实际访问，不是只看代码。
2. 主流程跑通：需求涉及的操作能完整点下来（点进去、切换、保存、返回）。
3. 控制台干净：没有 JS 报错、没有 404 资源。
4. 视觉达标：截图核对，尺寸/间距用实测数值说话（如「净距 18.9px，目标 18.8976px」）。
5. 回归不炸：改动涉及公共组件时，抽查其它使用该组件的页面没坏。
- **没验证的不说已验证。** 卡住了如实说卡在哪、需要什么。

**5. 汇报只说真话，带证据**
- 每项结论给可复核的证据：实测数值、截图路径、命令输出关键行、远端 commit sha。
- 明确的「没做/没测/风险」要单独列出来，不藏在正文里。
- 不用「应该可以」「理论上没问题」这种话交付。

**6. 审美与体验要给专业意见**
- 新 UI 必须和 v11 设计语言一致（同一套 CSS 变量、圆角、间距节奏、图标线宽），不引入风格冲突的东西。
- 做 UI 修改时，如果用户的方案有更好的现代做法，先说明「我按 A 做，另外建议 B，理由是…」，让用户选，不闷头照做也不擅自改方案。

## 三、同步与记录（规矩 7–9）

**7. 做完自动传仓库，不用提醒**
- 每次改动完成 → 本地 commit → 推回 `SummerWang829/total-mvp` main → 校验远端内容与本机一致（逐文件哈希比对）。
- 本机 git 协议被代理拦截时，走 GitHub API（blob → tree → commit → PATCH ref）。**大文件 base64 不能走命令行参数**（Windows 报「文件名或扩展名太长」），必须用 `--input` 传 JSON 文件。
- commit message 用中文说清「改了什么、为什么」，一个 commit 只做一件事。

**8. 每项工作记 PROGRESS.md**
- `docs/PROGRESS.md` 倒序记录，最新在最上面，每条含：做了什么、改了哪些文件、怎么验证的、还差什么、风险。
- 汇报前先更新 PROGRESS.md，再汇报（不能让记录落后于汇报）。
- 部署类条目必须写：备份文件名、回滚材料路径、部署后核对结果。

**9. 环境坑沉淀成文字**
- 踩过的坑写进本条或 PROGRESS.md，写清「症状 / 原因 / 解法」，后来的人不再重复踩。已知的见文末附录。

## 四、部署与线上安全（规矩 10–12）

**10. 动服务器前先出方案 + 只读侦察**
- 任何服务器变更（部署、改配置、动数据库）必须先：① 只读侦察现状（容器状态、文件数、有无进行中的访谈、数据库大小）；② 出方案说明要做什么、影响什么、怎么回滚；③ 用户点头再执行。
- 部署前必须确认：没有进行中的访谈/录制；线上 app 文件数与待部署版本一致（用于核对）。

**11. 部署必须留回滚材料**
- 数据库先备份（`/opt/total-mvp/deploy/backup.sh`，异地传 COS，确认 HTTP 200）。
- 代码留旧版 tgz（`/opt/rollback-code-<sha>.tgz`，不含 `deploy/.env`、secrets、数据库）。
- 镜像打旧标签（`total-app:rollback-<sha>`）。
- 部署只覆盖代码目录，`deploy/.env` 和 secrets 绝不动。

**12. 数据库与配置变更要可逆**
- 新增表/列必须写清迁移方式和回退方式，不删已有数据、不改已有字段语义。
- 环境变量新增要在 PROGRESS.md 写明「新增了哪个变量、在哪配、不配会怎样」。
- 密钥、token、密码一律不进仓库、不进聊天记录。

## 附录：已知环境坑（症状 / 原因 / 解法）

| 症状 | 原因 | 解法 |
|---|---|---|
| `git push` / `git clone` 502 | 本机代理拦截 github.com 的 git 协议 | 走 `gh api`（blob→tree→commit→PATCH ref）；拉取用 compare + contents API |
| 想读 `deepresearch` 源站却被拒（connection refused / 证书不对） | `43.159.98.75` 是 EdgeOne CDN 节点，不是源站 | 源站是 `43.160.208.195`（ubuntu 用户） |
| seed 脚本 404 / TypeError | httpx 0.28 严格 URL 合并丢 `base_url` 的 `/api` 前缀；本机代理 keep-alive 复用请求 | httpx 锁 0.27.x；脚本 monkey-patch `Connection: close` |
| 本地起服务浏览器访问 503 | 本机程序访问 localhost 必须走代理 | 用代理地址访问，或按现有脚本方式处理 |
| faster-whisper 转写崩 | `av>=15` 移除了 `metadata_errors` 参数 | 锁 `av==14.2.0`，不要升级 |
| 收起态圆点高度变 0 | 通用规则 `height:auto!important` 压制 | 用 `!important` 对抗，或提高选择器优先级 |
| 进招募问卷页自动化点击失败 | 页面自动弹 `.rq-pick-back` 选择框拦截 | 脚本先点 `#rfpickok` |
